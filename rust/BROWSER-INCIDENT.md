# 2.2 浏览器自动接入：停止发布

2026-10-16，测试环境报告关闭 VPN 后无法访问校园网。本轮 2.2 程序改动尚未提交或推送；此文档公开记录本地开发进展，不能将自动接入方案记为验收通过。

## 已确认的缺陷

持久 PAC 将非 Claude 网站的系统代理保存为快照。实机 Edge 策略中，普通网站仍指向创建规则时的 `127.0.0.1:7897`。守卫退出后不能同步系统代理变化；即使守卫运行，策略热刷新也尚未经过实机验证。这会让其他网站继续沿用旧代理，违反“其他网站跟随当前系统代理”的要求。

不能用添加 DIRECT 后备掩盖该问题：代理仍可连接但无法到达校园网时，后备不保证发生，且改变普通网站的路由语义。

## 已执行的恢复

- 使用安装器的浏览器移除助手撤回本应用的 Edge、Chrome ProxySettings；返回码 0。
- 复查两个本应用策略子项和两个 browser-proxy 登记文件均已移除。
- 没有清除 Cookie、登录资料、浏览器配置，也没有关闭现有浏览器。
- 未改系统代理、网络适配器、DNS 或 Clash 模式。
- 直连访问普通网站返回 HTTP 200；这不等同于校园网目标已恢复。校园网具体网址和用户复测结果仍待确认。
- 当时守卫已不在运行，未擅自重新启动。当前系统代理仍显示启用、Clash 端口仍在监听；不能据此判断用户报告发生时的开关状态。

## 用户补充与后续只读检查

用户确认出错的是校园网认证跳转页，浏览器显示 `www.msftconnecttest.com` HTTP 502；随后为继续交流切换到了手机热点。热点下，直连及通过当前 Clash 代理访问 connecttest.txt 均返回 200，redirect 返回 302。因此这些结果不能证明校园网已恢复。

复查 Chrome 两个配置与 Edge 默认配置，读取 Preferences / Secure Preferences 均成功，未发现守卫扩展登记或指向守卫的显式代理偏好。两浏览器新增策略和守卫浏览器登记仍不存在，守卫仍未运行。当前系统代理依然启用，等待用户关闭系统代理、切回校园网后复测；未代替用户切换 Wi-Fi 或修改其 Clash 配置。

## 后续约束

暂停此方案的安装、策略接入、真实网络切换测试与发布。不得把策略写入成功或一次保护域名路由成功，作为普通网站不受影响的证明。重新设计后，必须先通过守卫运行/退出、VPN 开/关、校园网认证、现有浏览器动态切换的交叉测试，再考虑部署。

现有自动化 71 项 Rust、16 项扩展测试已通过，但没有覆盖上述系统代理快照生命周期缺陷，不能据此宣称本版可交付。

## Melian 更名时的本机防复发措施

应用展示名、快捷方式、安装包和说明改为 Melian，已有安装目录和协议名称保持兼容。自动接入入口、后台策略同步、提权助手的新接入路径均由停用开关拦截，原有移除功能保留。面板显示「网页保护暂时停用」，不再展示启用或重开浏览器按钮；安装后调用 `--enable-web` 实测返回停用错误，两浏览器策略仍不存在。

本轮完整构建通过 71 项 Rust 和 16 项扩展测试；Windows 原生上下文确认桌面与开始菜单的 Melian 快捷方式有效，旧快捷方式已移除，「已安装的应用」名称为 Melian。系统代理值未改变。界面验证产生的位置记录已从精确匹配的升级前备份恢复，设置文件 SHA-256 与升级前一致。验证后恢复到升级前的退出状态，自启偏好继续保留；没有进行 Windows 重启验收。
