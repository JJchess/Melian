## Windows 实测

- 使用现有 Codex 登录成功读取额度与正常重置时间，同时获取公告 feed 和 timeline。
- 75 秒观察中，账号成功更新两次，间隔约 62 秒（包含请求耗时）；公告更新一轮。未创建任务或兑换重置。
- 重复调用监测 start，仍只有一个 Codex App Server 子进程。
- 正常退出只读探针后子进程退出；强制结束探针后，两秒内其 Codex 子进程也已消失。
- 150% 缩放下检查了 Codex 面板，文本与按钮没有重叠。Esc 收起后外框为 63 像素高，对应 34 DIP 胶囊与 8 DIP 绘制边距。
- 静止两秒内新增绘制帧数为 0。倒计时按分钟更新，不连续重绘。

## 资源占用

使用优化构建的独立只读探针，等待 20 秒后采样 30 秒；这是监测模块与其官方子进程的测量，不是完整桌面应用的总内存或与旧版的差值。

| 进程 | 工作集 | 私有内存 | 30 秒 CPU 时间增量 |
| --- | ---: | ---: | ---: |
| 监测探针 | 12.41 MiB | 4.09 MiB | 0.0312 秒 |
| Codex App Server | 91.98 MiB | 26.19 MiB | 0.3594 秒 |

Codex 子进程包含共享映像页，工作集不能当作全部新增物理内存。数据是本机单次观察，不是跨设备性能保证。
