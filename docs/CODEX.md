# Codex 额度与重置提醒

点击 Melian 菜单里的 **Codex**，查看本机 Codex 当前登录账号的剩余额度、正常重置时间，以及 Tibo 的明确重置预告。信息在原来的小面板内展开，不需要配置 X 密钥或重新登录。

## 账号额度

Melian 自动寻找已安装的 Codex，使用官方 App Server 的只读账号接口。Windows 优先使用 Codex 桌面应用附带的程序；Mac 查找 Codex.app、常见 CLI 位置与 PATH。保留已有 CODEX_HOME 和代理环境，不复制登录凭据。

额度每分钟查询一次；打开详情、睡眠恢复和重置时间到达时触发限流后的刷新。查询期间账号有变化时丢弃旧结果。多个额度窗口可用“额度 1/2”切换查看，菜单显示最紧张的窗口，不假设每种订阅都有五小时限制。

时间按电脑当前时区显示。倒计时到零只表示需要重新查询，并不证明额度已经恢复。查询失败保留上次数据并标识，三分钟未更新视为过期。未安装、未登录、API Key 等不支持订阅额度的登录方式会显示相应说明。

只监测本机 Codex 所使用的账号，不汇总其他 CODEX_HOME、远程环境或其他账号。不同客户端分别登录时，以实际连接的本机 Codex 为准。

## Tibo 预告

公告来自 **[codex-reset.com](https://codex-reset.com/)** 公开聚合接口，并链接到 [Tibo 的 X 账号 @thsottiaux](https://x.com/thsottiaux) 原帖。这是社区来源，可能延迟、遗漏或更正，不是 OpenAI 官方数据接口。

- 只展示明确的额度重置消息，不使用历史概率预测。
- “两小时内”从原帖发布时间计算；模糊日期或时区只显示说明，不生成精确倒计时。
- “Tibo 已报告完成”“社区报告已重置”和“本人额度恢复”分别显示，以账号实际查询结果为准。
- 额外赠送的手动重置次数不等于额度已经重置，Melian 不自动兑换。
- 公告每两分钟检查，遵守缓存期限与限流要求。失败显示“暂无法更新”，不会当成“暂无预告”。
- 公告边上的来源和原帖链接可直接打开，长文以原帖为准。

面板分别显示**原帖发布时间**和**来源抓取时间**。刷新成功只说明取到了聚合源的快照，不代表直接实时读取了 Tibo 的 X 时间线。“来源中未发现明确预告”仅描述该来源收录的数据，不保证没有新帖。来源自身的快照超过五分钟也会标为过期，不能用本机查询时间掩盖来源延迟。

支持每日系列中的不同重置表述，以及同一作者连续回复中的时间补充、更正和完成说明。例如“it's reset day today”及其回复“Lands tomorrow before 10am PST.”会作为预告显示；由于相对日期和 PST 在夏令时期间有歧义，保留发布时间与原文，不生成倒计时。历史记录接口暂时不可用时，新预告仍可显示；历史记录确认只表示社区报告，不能证明本人账号恢复。

新明确预告或已用尽的额度恢复时，小面板展开六秒，不抢焦点。收起后的小点保留到查看或操作 Codex 面板。首次接入不会弹出历史消息；Claude 网络异常优先显示。

## 数据与运行

监测与 Claude 的网络阻断相互独立。不启动 Codex 任务、不读取聊天内容、不改变系统或浏览器代理。退出时只结束 Melian 自己启动的监测子进程，已有 Codex 工作进程继续运行。

公告缓存和提醒去重记录位于现有用户数据目录的 `codex-monitor.json`。不保存令牌、邮箱、账号指纹或聊天内容，也不向公告来源发送账号信息。公开 API 请求用 Melian 的 User-Agent 标识项目。

本机兼容协议增加可选 `state.codex`，包含额度窗口、公告、更新时间、过期状态与提醒信息；`codexRefresh` 请求刷新，`codexRead` 清除未读标记。原有网络状态和操作不变。

开发者可运行只读实测：

```sh
cargo run --manifest-path rust/Cargo.toml -p guard-platform --example codex_probe -- 75
```

该检查读取真实账号和公开公告，只输出可用性、剩余比例和更新状态，不输出账号标识。会写入正常公告缓存；不修改代理设置。

参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[公告 API](https://codex-reset.com/developers)。

测试结果、资源占用及尚待实机验证的项目见 [验收记录](CODEX-VALIDATION.md)。
